# ADR-0002: Fixture ingress format is eslogger NDJSON first

Status: proposed
Date: 2026-10-15
Clarifies: SPEC.md §0.8, §4.5, §7

## Context

The SPEC.md draft named two NDJSON shapes for fixtures: recorded `eslogger` output (§0.8,
§7) and NDJSON of the decoded `PLRawEvent` struct written by `porchlightctl record` (§4.5).
Until Apple grants the Endpoint Security entitlement, `eslogger` is the only source of real
events on a development machine, and M1's acceptance test (round-trip a 10k-event fixture)
needs real data.

## Decision

- `porchlightctl replay` accepts `eslogger` NDJSON from M1. The adapter maps eslogger's
  `process`, `event`, `seq_num`, `global_seq_num`, `mach_time` and `time` fields into
  `Event`. Unknown event names are preserved as `unsupported` with the raw name so coverage
  gaps are visible rather than silent.
- Porchlight raw-event NDJSON (the decoded `PLRawEvent`) is added in M3 when the extension
  exists to produce it. `replay` detects the format from the first line.
- `scripts/record-fixture.sh` wraps `eslogger` with exactly the §4.2 event set and documents
  the Full Disk Access requirement on the terminal.
- Fixtures are recorded by a human on a real machine and committed under `Fixtures/`.
  Golden outputs (`findings.json`, graph and inventory snapshots) are generated by
  `porchlightctl` and committed next to them.

## Consequences

- M1 is testable end to end against real data before any extension code exists.
- Two adapters to maintain once M3 lands. They share the `Event` target and tests.
- `eslogger` output may differ across macOS versions. The adapter is versioned on eslogger's
  `schema_version` field and rejects unknown versions loudly.
- The repository guard quarantines `**/*.ndjson`. Agents cannot read or write fixtures
  without the human unlocking a path. This is accepted as a provenance control; the human
  decides whether to exempt `Fixtures/**`.
